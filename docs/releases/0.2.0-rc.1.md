# Sapflow 0.2.0-rc.1

This is a coordinated opt-in source prerelease of the existing `sapflow-core`,
`sapflow-srt`, `sapflow-hls`, `sapflow-rtmp` and `sapflow` crates on crates.io.
It packages the server and libraries from main at `87fed908`, with release
metadata and these migration notes added. The other workspace crates remain
unpublished. There are no new binary, container, mobile or SDK release channels.

```sh
cargo install sapflow --version 0.2.0-rc.1 --locked
cargo add sapflow-srt@=0.2.0-rc.1
```

Use Rust 1.94 or later, edition 2024. The release is verified with Rust 1.94.1.
This is an experimental release candidate, not a stable or fully qualified
library release. Existing 0.1 users must opt in explicitly. These APIs remain
pre-1.0; update all directly used Sapflow crates together.
The crate archives include their MIT licence and source. Registry dependencies
retain their own licences and source; downstream binary and container builders
must retain the relevant third-party notices.

## Migration from 0.1.0

- `sapflow_srt::receiver::Receiver::take_delivery` now returns
  `Option<(Vec<u8>, bool)>`. The boolean marks a transport discontinuity before
  the payload. Notify MPEG-TS ingest of that gap before passing it the bytes;
  do not discard the flag. New public statistics also require updates to
  exhaustive struct construction or destructuring.
- `sapflow-core::Health::keyframe_interval_ms` is now `Option<u64>` because
  audio-only streams have no video keyframes. Preserve absence rather than
  inventing a zero interval.
- HLS `Segment::data` is now `SegmentData`, whose `chunks()` are immutable
  payloads in wire order. Stream the chunks and use `len()` for the complete
  response length. Joining them for every viewer defeats the shared storage.
- HLS media admission is fallible. Propagate the errors from `EsIngest::audio`
  and other checked ingest/muxer operations, including resource refusal.
  Audio-only ingest uses `audio_at` with caller-supplied wall time and handles
  its returned update. Use the documented track declaration and terminal-drain
  APIs; a transport close does not itself prove complete media.
- The server uses its own viewer HTTP event loop. Remove any
  `SAPFLOW_HTTP_IMPL=hyper` setting; that removed backend is rejected at startup.
  Review the current configuration and recording/session contracts before
  replacing a 0.1.0 origin.

The public API documentation and crate examples describe the current calls.
This list highlights the principal breaks; it is not a compatibility promise
for every pre-1.0 struct field or enum match.

## Performance and acceptance

The release retains the SRT first-occupied-slot cache and the conventional HLS
playlist cache. The [qualification results](../performance-qualification-results-2026-11-11.md)
record exact workloads, source identities and limits. Linux SRT qualification
passed. The playlist result is a warm-response construction microbenchmark,
not evidence of a whole-server CPU or latency improvement. Targeted HTTP
notifications failed the predeclared benefit gate and were removed.

Correctness CI covers Rust tests and Clippy, smoke playback/recording,
Android/iOS generated SDK checks, browser scheduling and bounded fuzzing.
Physical show-length, mobile store, complete V4V production-show and wider
library acceptance remain open in [readiness](../readiness.md) and the
[library quality plan](../library-quality-plan.md). This source release does
not close those gates or change any deployed origin.

## Release verification

Build all five packaged crates and exercise an external package consumer before
publication, using Cargo's
multi-package staging so dependencies resolve to the proposed 0.2.0-rc.1 archives.
Verify the normal CI for the exact reviewed release revision before merging.
Tag the exact merged publication source as `v0.2.0-rc.1`. Publish dependencies
before their consumers: core and SRT, HLS, RTMP, server.
After publication, verify every registry archive checksum and Git source ID,
then install the server from crates.io with `--locked` and run `sapflow --help`.
Retain compact hashes and commands rather than raw logs or copied archives.
